Leadflow — Architecture Diagram

System overview: components, dependencies, data flow

Browser (User)
Next.js 16 · React 19
Frontend — port 3000
  • Public enquiry form (/)
  • Login page (/login)
  • Magic-link callback (/auth/login)
  • Staff leads inbox (/leads)
  • Tailwind CSS for styling
  • Session via httpOnly cookie
HTTP REST (JSON) · CORS · httpOnly cookie session · port 8000
Docker Compose — service: backend
FastAPI · Python · Uvicorn
Backend — port 8000
  • POST /leads — public, create lead
  • GET /leads — auth, paginated + filtered
  • GET /leads/{id} — auth, single lead
  • PATCH /leads/{id} — auth, update status/note
  • DELETE /leads/{id} — auth, soft-delete
  • POST /auth/magic-link — send login email
  • POST /auth/login — redeem token → session
  • POST /auth/logout — destroy session
  • Staff allowlist checked at login request
  • Alembic runs migrations on startup
SQLite · Docker volume: sqlite_data
Database — file: /app/data
leads
  • id, name, email, company
  • phone, source, message
  • status, note
  • created_at, updated_at, deleted_at
magic_links
  • id, email, token_hash
  • created_at, expires_at, used_at
sessions
  • id, email, token_hash
  • created_at, expires_at
HTTPS API call on magic-link request (token hash stored, never raw token)
External Service
resend.com — Transactional Email API
Resend Email
  • Sends magic-link login emails to staff
  • Auth via RESEND_API_KEY env var
  • Sender address: RESEND_SENDER_EMAIL
  • If call fails, login URL still logged server-side

Notes: Frontend is not inside Docker Compose — run separately with npm run dev (port 3000). Backend Docker Compose service builds from ./backend/Dockerfile and mounts an SQLite volume. Demo seed data (15 leads) is generated on first startup when GENERATE_DEMO_DATA=true. All tokens are hashed (SHA-256) before storage — raw tokens never touch the database.
